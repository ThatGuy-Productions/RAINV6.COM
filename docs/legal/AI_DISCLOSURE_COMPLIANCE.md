# RAIN V6 Beta — AI Disclosure & Compliance

**Effective Date:** 31 July 2026

**Last Updated:** 31 July 2026

## 1. Purpose

This document sets forth RAIN V6 Beta's compliance posture with respect to artificial intelligence disclosure obligations, including the **EU AI Act (Regulation 2024/1689)**, the **DDEX ERN 4.3.2 AIInvolvement standard**, and the **C2PA v2.2 content provenance specification**.

It also describes how the RAIN chain-of-custody module (`src/lib/rain/chain-of-custody.ts`) handles AI-generated source material and communicates AI involvement to users and downstream systems.

## 2. EU AI Act — Article 50 Compliance

### 2.1 Overview

The EU AI Act's Article 50 (Transparency Obligations for Providers and Deployers of Certain AI Systems) comes fully into effect on **2 August 2026**. It requires that outputs generated or materially manipulated by AI systems be labelled as such when they constitute "deep fakes" or could be mistaken for authentic human-created content.

### 2.2 RAIN's Position Under Article 50

RAIN V6 is an **AI-assisted audio mastering tool**, not an AI content generator. The Service does not generate new musical content — it processes existing audio through:

- Loudness normalisation
- Equalisation (8-band parametric)
- Multiband compression (3-band)
- Stereo enhancement
- Spectral repair
- True-peak limiting

These are traditional audio engineering operations parameterised by AI inference (RainNet v2). The creative content of the audio — the composition, performance, and arrangement — is not generated by RAIN.

### 2.3 Transparency Measures

RAIN provides the following transparency measures to support Article 50 compliance:

| Measure | Implementation | Reference |
|---------|---------------|-----------|
| RAIN-CERT provenance certificate | Ed25519-signed document of processing chain | `src/lib/rain/provenance.ts` |
| Custody certificate | Documents AI detection, stripping, and ownership declaration | `src/lib/rain/chain-of-custody.ts` |
| AI involvement disclosure | Per-stage declaration (vocals/instrumentation/composition/mixing/mastering) | AIInvolvement type in `chain-of-custody.ts` |
| Export metadata | Embedded RAIN processing info in output files | See Section 4 |
| User-controlled disclosure | Users can declare AI involvement levels | See Section 7 |

### 2.4 RAIN-CERT As Transparency Artefact

The RAIN-CERT certificate provides a verifiable, cryptographically signed record of what processing was applied. This certificate:

- Does not add AI-generated claims to the user's audio
- Documents only RAIN's own processing
- Can be shared with distributors, DSPs, and rights organisations
- Is independently verifiable using the embedded Ed25519 public key

## 3. C2PA v2.2 Compliance Status

### 3.1 What C2PA Is

The Coalition for Content Provenance and Authenticity (C2PA) specification defines a standard for embedding provenance metadata (manifests) in digital content. C2PA v2.2 is the current specification as of 2026.

### 3.2 RAIN's C2PA Implementation

RAIN V6 generates C2PA v2.2-compatible manifests through `src/lib/rain/provenance.ts`:

```typescript
const manifest: C2PAManifest = {
  version: '2.2',
  claimGenerator: `RAIN/6.0.0-rc1`,
  actions: [
    { action: 'c2pa.audio.mastered', parameters: { engine: 'RAIN-DSP-Web-v6' }, when: now },
    { action: 'c2pa.audio.dsp', parameters: { params: JSON.stringify(params) }, when: now },
    { action: 'c2pa.audio.analyzed', parameters: { analysis: JSON.stringify(analysis) }, when: now },
  ],
  assertions: [
    { label: 'c2pa.actions.v2', data: { actions: ['mastered', 'dsp', 'analyzed'] } },
    { label: 'org.rain.cert.level', data: { level: 'RAIN-CERT-1', algorithm: 'Ed25519' } },
    { label: 'org.rain.watermark', data: { type: 'none', embedded: false, note: 'AudioSeal not available in-browser' } },
    { label: 'org.rain.fingerprint', data: { type: 'Chromaprint', hash: fingerprint ?? null, frames: 32, bands: 8 } },
  ],
}
```

### 3.3 Compliance Status

| C2PA v2.2 Feature | Status | Notes |
|-------------------|--------|-------|
| Manifest structure | ✅ Compliant | JSON-encoded per spec |
| Version field | ✅ v2.2 | Declared in manifest |
| Action assertions | ✅ Compliant | Audio mastering, DSP, analysis |
| Custom assertions | ✅ Compliant | org.rain.* namespace |
| Ed25519 signing | ✅ Compliant | Web Crypto API (non-extractable private key) |
| CBOR encoding | ⚠️ JSON only | CBOR (RFC 8949) not yet implemented; JSON is used for signing |
| Embedding in WAV | ⚠️ Partial | Manifest included in RAIN-CERT JSON; direct WAV chunk embedding pending |
| Embedding in MP3 | ⚠️ Partial | Manifest included in RAIN-CERT JSON; ID3v2 PRIV frame pending |
| Ingestor verification | ⚠️ Not tested | No independent C2PA ingestor has validated RAIN manifests |

### 3.4 Intended Improvements

Before commercial release, RAIN aims to:

1. Implement CBOR encoding for full C2PA v2.2 compliance
2. Embed C2PA manifests directly in WAV chunks and ID3v2 PRIV frames
3. Validate manifests against a reference C2PA ingestor
4. Add C2PA trust list integration

## 4. DDEX ERN 4.3.2 AIInvolvement Block

### 4.1 Standard Overview

DDEX ERN (Electronic Release Notification) version 4.3.2 introduced an `AIInvolvement` composite block that allows rights holders to declare how AI was used in the creation of a musical work. This is the music industry's standard mechanism for AI disclosure in distribution metadata.

### 4.2 RAIN's Implementation

RAIN V6 generates DDEX ERN 4.3.2 packages through `src/lib/rain/distribution.ts` and `src/lib/rain/distribution-multitrack.ts`. The AIInvolvement block is populated based on the chain-of-custody module's AI involvement declaration:

```typescript
// From src/lib/rain/chain-of-custody.ts
export interface AIInvolvement {
  vocals: AIInvolvementLevel        // 'none' | 'assisted' | 'generated'
  instrumentation: AIInvolvementLevel
  composition: AIInvolvementLevel
  mixing: AIInvolvementLevel
  mastering: AIInvolvementLevel
  notes?: string
}
```

### 4.3 Per-Stage Disclosure

The DDEX AIInvolvement block RAIN generates includes:

| DDEX Field | RAIN Source | Description |
|------------|-------------|-------------|
| `IsAIGenerated` | `aiInvolvement.composition === 'generated'` | Whether composition was AI-generated |
| `IsAIAssisted` | `aiInvolvement.* === 'assisted'` | Whether AI assisted in any stage |
| `AIToolName` | Derived from `strippedSources[].tool` | Name of AI tool used (e.g., Suno, Udio) |
| `AIToolVersion` | Not captured | AI tool version not reliably detectable |
| `AIInvolvementDescription` | `aiInvolvement.notes` | Human-readable description |
| `MasteringEngine` | `RAIN-DSP-Web-v6` | RAIN V6 mastering engine identifier |

### 4.4 User Responsibility

**The AIInvolvement declaration in the DDEX package reflects what the user has declared.** RAIN does not independently determine whether audio was AI-generated — it can only detect known AI tool metadata signatures. The user is responsible for the accuracy of the AI involvement declaration in their DDEX submissions.

## 5. Chain of Custody: How RAIN Handles AI Metadata

### 5.1 The Problem

AI music generation tools (Suno, Udio, AIVA, Mubert, Boomy, Soundraw, Beatoven) embed metadata in exported audio files that may contain claims about AI authorship. When a user creates content using these tools and then masters it with RAIN, the existing AI metadata can create confusion about ownership.

### 5.2 RAIN's Solution

The `src/lib/rain/chain-of-custody.ts` module implements a complete AI metadata detection, stripping, and replacement pipeline:

#### Step 1: Detection

The module scans uploaded audio files for AI-generated metadata from seven known AI tools:

```typescript
export const AI_DETECTION_PATTERNS: readonly AIDetectionPattern[] = [
  { tool: 'suno',     priority: 1, ... },  // 14 detection rules
  { tool: 'udio',     priority: 1, ... },  // 12 detection rules
  { tool: 'aiva',     priority: 2, ... },  // 9 detection rules
  { tool: 'mubert',   priority: 2, ... },  // 6 detection rules
  { tool: 'boomy',    priority: 2, ... },  // 6 detection rules
  { tool: 'soundraw', priority: 2, ... },  // 6 detection rules
  { tool: 'beatoven', priority: 2, ... },  // 6 detection rules
  { tool: 'unknown-ai-generator', priority: 99, ... },  // Generic AI detection
]
```

Detection examines:
- WAV RIFF INFO chunk fields (ID + value)
- BWF bext chunk fields (Description, Originator, OriginatorReference)
- ID3v2 frame IDs and text values (TSSE, TENC, TCOP, TPUB, TCOM, TXXX, COMM)
- Non-standard chunk IDs
- Audio watermark signatures (LSB-based patterns)

#### Step 2: Stripping

All detected AI metadata is stripped from the audio file:

- Detected RIFF INFO fields are removed
- AI-marked BWF bext chunks are removed
- Junk/PAD chunks (often used for hidden AI metadata) are removed
- Non-standard chunks matching AI tool IDs are removed
- Detected ID3v2 frames are removed
- LSB watermarks in PCM audio data are cleared (see `removeLSBWatermark()`)

#### Step 3: Custody Certificate

A complete custody certificate is generated documenting:

- Original creator (the user)
- Detected and stripped AI sources
- RAIN V6 processing stages applied (13 stages)
- Final RAIN-CERT provenance

The certificate is embedded in:
- WAV: RIFF INFO 'CUST' field
- MP3: ID3v2 PRIV frame (`com.rain.custody` owner)
- C2PA manifest: `org.rain.custody` assertion

### 5.3 The Ownership Principle

**The chain-of-custody module operates on the principle that the human user is the sole owner and creator of the final work, regardless of any AI generation or assistance.** The module:

- Strips AI tool metadata claims (which may assert or imply AI authorship)
- Replaces them with correct ownership declarations naming the human creator
- Documents what was stripped for full transparency
- Never claims RAIN ownership over the user's content

### 5.4 Mixed Source Handling

For works where some stems are human-created (e.g., vocals) and others are AI-generated (e.g., Suno instrumental), the module generates a `MixedSourceInfo` record:

```typescript
export interface MixedSourceInfo {
  humanStems: string[]   // e.g., ['vocals', 'guitar']
  aiStems: string[]      // e.g., ['drums', 'bass', 'other']
  aiTool: string         // e.g., 'suno'
  description: string    // Free-text explanation
}
```

## 6. Per-Tool AI Disclosure Handling

### 6.1 Supported AI Music Generators

RAIN's chain-of-custody module detects and handles metadata from the following AI music generation tools:

#### Suno
- **Detection confidence:** High (14 detection rules, multiple metadata formats)
- **Metadata fields stripped:** ISFT, IENG, ICMT, ITOO, TSSE, TENC, TCOP, TPUB, TCOM, and any custom field containing "suno"
- **ID3v2 frames stripped:** TSSE, TENC, TCOP, TPUB, TCOM, TPE1, TPE2, TXXX, COMM, WOAR
- **Watermark:** LSB-based pattern `SUNO` + 16-bit seed — detected and removed
- **User action required:** Users should declare AI tool usage level (generated/assisted/none) in the RAIN interface

#### Udio
- **Detection confidence:** High (12 detection rules)
- **Metadata fields stripped:** ISFT, IENG, ICMT, TSSE, TENC, TCOP, TPUB
- **ID3v2 frames stripped:** TSSE, TENC, TCOP, TPUB, TXXX, COMM
- **Watermark:** LSB-based pattern `UDIO` + 16-bit seed — detected and removed
- **User action required:** Same as Suno

#### AIVA
- **Detection confidence:** Medium-High (9 detection rules)
- **Metadata fields stripped:** ISFT, IENG, ICMT, TCOM, and fields containing "aiva" or "aiva.ai"
- **ID3v2 frames stripped:** TCOM, TENC, TXXX
- **Watermark:** No known watermark pattern
- **User action required:** Users should review AIVA's license terms regarding commercial use of generated compositions

#### Mubert
- **Detection confidence:** Medium (6 detection rules)
- **Metadata fields stripped:** ISFT, ICMT, and fields containing "mubert" or "mubert.com"
- **ID3v2 frames stripped:** TENC, TXXX
- **Watermark:** No known watermark pattern
- **User action required:** Users should review Mubert's license terms

#### Boomy
- **Detection confidence:** Medium (6 detection rules)
- **Metadata fields stripped:** ISFT, ICMT, and fields containing "boomy" or "boomy.com"
- **ID3v2 frames stripped:** TENC, TXXX
- **Watermark:** No known watermark pattern
- **User action required:** Users should review Boomy's license terms

#### Soundraw
- **Detection confidence:** Medium (6 detection rules)
- **Metadata fields stripped:** ISFT, ICMT, and fields containing "soundraw" or "soundraw.io"
- **ID3v2 frames stripped:** TENC, TXXX
- **Watermark:** No known watermark pattern
- **User action required:** Users should review Soundraw's license terms

#### Beatoven
- **Detection confidence:** Medium (6 detection rules)
- **Metadata fields stripped:** ISFT, ICMT, and fields containing "beatoven" or "beatoven.ai"
- **ID3v2 frames stripped:** TENC, TXXX
- **Watermark:** No known watermark pattern
- **User action required:** Users should review Beatoven's license terms

#### Generic / Unknown AI Generators
- **Detection confidence:** Low-Medium (10 generic detection rules)
- **Rules detect:** Phrases like "AI-generated," "created with AI," "generated by artificial intelligence"
- **User action required:** If a tool is detected as "unknown-ai-generator," users should manually review and declare the AI involvement level

### 6.2 Limitations of Detection

The AI detection system has the following known limitations:

- **Re-encoded files:** If audio has been re-encoded through another tool, AI metadata may have been stripped or altered, preventing detection
- **New AI tools:** Tools not in the detection table will only be caught by generic rules (lower confidence)
- **Tool version changes:** AI tools may change their metadata formats in updates; detection may miss fields from newer versions
- **Intentional removal:** If a user has already stripped AI metadata before uploading to RAIN, the module will find nothing to detect
- **False positives:** Generic detection rules may match legitimate uses of AI-related terminology in non-AI contexts

## 7. User's Obligations for AI Disclosure

### 7.1 Declaring AI Involvement

Users of RAIN V6 are responsible for accurately declaring AI involvement in their works. RAIN provides the interface for this declaration but does not validate its accuracy. Users should:

1. **Know their source material:** Understand whether and how AI tools were used to create the audio being mastered
2. **Declare honestly:** Provide accurate AI involvement levels per production stage
3. **Document their process:** Maintain records of their creative process for audit purposes
4. **Understand platform requirements:** Different DSPs and distributors have different AI disclosure requirements

### 7.2 Consequences of False Declaration

Submitting false or misleading AI involvement declarations to DSPs, distributors, or rights organisations may result in:

- Rejection of the release by the distributor or DSP
- Removal of content from streaming platforms
- Loss of revenue or royalty payments
- Legal liability for fraud or misrepresentation
- Violation of the terms of service of the AI tool used to create the content
- Regulatory penalties under applicable AI disclosure laws

### 7.3 Recommended Disclosure Practices

We recommend that users:

- Declare AI involvement even when uncertain ("assisted" is safer than "none" when AI tools were used)
- Include AI involvement notes in the DDEX AIInvolvement block's description field
- Retain RAIN-CERT certificates as evidence of the processing chain
- Consult legal counsel for high-stakes releases involving AI-generated content
- Review the terms of service of the AI tool used to generate source material

## 8. Jurisdictional Considerations

### 8.1 EU AI Act (Effective 2 August 2026)

Users distributing music to EU markets should be aware of the EU AI Act's transparency requirements. RAIN's RAIN-CERT and custody certificate outputs can serve as documentation to demonstrate compliance.

### 8.2 South Africa

South Africa does not currently have AI-specific disclosure legislation equivalent to the EU AI Act. However, the general principles of POPIA, consumer protection law, and common law regarding misrepresentation apply to AI-related claims.

### 8.3 United States

The US does not currently have comprehensive federal AI disclosure legislation. State-level laws (e.g., California, New York) are evolving. The FTC has indicated that misleading claims about AI involvement may constitute deceptive trade practices.

### 8.4 Other Jurisdictions

Users distributing globally should consult local legal requirements for AI disclosure. RAIN provides tools to support disclosure but does not provide legal advice regarding specific jurisdictional compliance.
